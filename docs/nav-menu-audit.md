## 二、关键澄清：父级本身就是页面

这一点你说得对，也和 `trainingtowers.com` 的做法一致。

**trainingtowers.com 的菜单结构**（摘自其 HTML）：父级点进去后，子菜单第一项就是父级自身页面：

```
FIXED TOWER
├── FIXED TOWER        ← 父页自身
├── Alarm Series
└── Build-A-Tower

MODULAR TOWERS
├── MODULAR TOWERS     ← 父页自身
├── MODx Series
├── MODx vs Containers
└── Build-A-MODx

ACCESSORIES
├── Accessories        ← 父页自身（配件总览）
├── Maritime
├── Tactical Training
└── Hazmat
```

**当前站点已经是这个模式**：`Header.tsx` 抽屉钻取时，会把 `activeItem.href`（父页）作为第一项渲染，随后才是子项。所以：

- `固定训练塔`（`/fixed-tower`）、`模块化训练塔`（`/modular-tower`）、`训练配件`（`/accessories`）父级**都是可点击的真实页面**。
- 抽屉里点「训练配件」，第一项就是「训练配件 → /accessories」，下面才是海事 / 战术 / 危化品。

> 所以真正的问题不是「父级不能点」，而是 **命名语义** 和 **分组归属** 让人误解：把「海事 / 战术 / 危化品」这类**训练场景方案**挂在名为「配件」的父级下。

## 三、菜单名 vs 内容 匹配审计

| 一级菜单 | 子项 | 对应页面主体内容 | 名实是否匹配 | 问题 |
|----------|------|------------------|:---:|------|
| 为什么选我们 | 发展历程 / 核心团队 / 资质认证 / 全球业务 | 公司介绍类 | ✅ | 案例内容藏在「全球业务」里，无独立入口 |
| 固定训练塔 | 标准塔型系列 / 定制训练塔 | 固定塔产品 | ✅ | 父级即产品页，正常 |
| 模块化训练塔 | 模块化系列 / vs 集装箱 / 定制模块化 | 模块化塔产品 | ✅ | 父级即产品页，正常 |
| 燃烧室 | 互锁隔热衬里 / 衬里方案对比 | 燃烧室产品 | ✅ | 正常 |
| **训练配件** | **海事训练 / 战术训练 / 危化品训练** | `/accessories` 是配件道具总览；三个子项是**专项训练场景方案** | ❌ | 「配件」父级下挂的是「训练方案」，语义错位 |
| 资源中心 | 如何采购 / 设计中心 / 年检 / FAQ / 展会 / 媒体报道 / 质保 / 博客 | 采购服务 + 内容资讯混合 | ⚠️ | 8 个子项过载；服务类与内容类混在一起 |
| 联系我们 | — | 联系表单 | ✅ | 正常 |

### 核心诊断

1. **「训练配件」名实不符**：页面主体是「配件与道具总览」（热与烟、破拆、逃生、绳索…共 10+ 类），但子菜单只露出海事 / 战术 / 危化品三个**专项训练方案**，看不到配件总览的分类，导致「训练配件 = 三个训练产品」的错觉。
2. **「资源中心」意图过载**：把采购流程、年检、质保（**服务**）与博客、新闻（**内容**）塞进同一菜单，8 个子项过多，两类用户路径被混合。
3. **案例无入口**：高转化的工程案例内容藏在首页区块和 `/why-us/global`，主导航完全没有「案例」。
4. **Footer 与 Header 不一致**：Footer「产品系列」把「海事训练」平铺在产品下，与 Header 的层级又不同，进一步加深混乱。

## 四、重组方案

### 方案 A：独立「专项训练」（推荐）

把「专项训练方案」从「配件」中拆出，各归其位。改动集中在 `NAV_ITEMS`，无需大改页面。

| 一级 | 二级（父级自身为第一项） | 变化 |
|------|--------------------------|------|
| 为什么选我们 | 为什么选我们 / 发展历程 / 核心团队 / 资质认证 / 全球业务 | 不变 |
| 固定训练塔 | 固定训练塔 / 标准塔型系列 / 定制训练塔 | 不变 |
| 模块化训练塔 | 模块化训练塔 / 模块化系列 / vs 集装箱 / 定制模块化 | 不变 |
| 燃烧室 | 燃烧室 / 互锁隔热衬里 / 衬里方案对比 | 不变 |
| **配件与道具** | 配件与道具（`/accessories`） | 「训练配件」→「配件与道具」，明确是 catalog |
| **专项训练**（新一级） | 海事训练 / 战术训练 / 危化品训练 | 从配件独立成一级 |
| **工程案例**（新一级） | `/cases` 列表页 | 需新建列表页 |
| 资源与服务 | 如何采购 / 设计中心 / 年检 / FAQ / 展会 / 质保 | 「资源中心」改名，剥离博客/新闻 |
| 联系我们 | — | 不变 |

- 博客、新闻归入 **Footer「洞察」** 或资源与服务底部，避免与服务文档抢注意力。
- 优点：语义最清晰；缺点：一级项从 7 增至 8-9，需注意窄屏折叠（现有 `NAV_HIDE` 已按断点隐藏）。

### 方案 B：四大板块收敛（中期，最贴 B2B）

顶部只留 5 个一级：

```
产品        → 抽屉内分组：训练塔（固定/模块化）| 燃烧室 | 配件与道具 | 专项训练
工程案例    → /cases（需新建）
客户资源    → 如何采购 / 设计中心 / FAQ / 年检 / 质保
关于拓之迹  → 为什么选我们 / 团队 / 认证 / 全球业务
联系我们
```

博客、新闻放 Footer + 「洞察」。优点：信息架构最干净；缺点：改动量大，需要抽屉支持「分组标题」。

### 方案 C：最小改动（只修「配件」这一处）

保持 6 个产品一级不变，只改「训练配件」的命名与内部分组：

```
配件与专项训练              ← 由「训练配件」改名
├── 配件与道具总览   → /accessories   （父级自身，本就存在）
├── —— 专项训练方案 ——     （分组标题，不可点）
├── 海事训练         → /accessories/maritime
├── 战术训练         → /accessories/tactical
└── 危化品训练       → /accessories/hazmat
```

同时把 `/accessories` 页面里三个专项区块的 eyebrow 从「海事训练 / 战术训练」改为「专项训练方案 · 海事 / · 战术」，与菜单语义对齐。优点：改动最小、当天可上线；缺点：语义仍略绕，「配件」和「训练」仍同层。

## 五、配套页面建议（与菜单一起改效果最佳）

| 动作 | 优先级 | 理由 |
|------|:---:|------|
| 新建 `/cases` 案例列表页 | 高 | 案例有独立入口，不再误链到 `/why-us/global` |
| 首页 & 详情页「查看全部案例」改指向 `/cases` | 高 | 与新入口一致 |
| 「资源中心」→「资源与服务」，剥离博客/新闻 | 中 | 区分服务文档 vs 内容资讯 |
| 博客/新闻升级为「洞察」或进入 Footer 主列 | 中 | 缓解资源中心 8 项过载 |
| Footer「产品系列」与 Header 层级对齐 | 中 | 避免「海事训练」在 Footer 被当作产品平铺 |
| `/accessories` 加「配件 vs 专项方案」说明段 | 低 | 帮助首访用户理解结构 |
