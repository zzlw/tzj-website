## 一、背景与目标

### 1.1 为什么优先改这一页

`/zh-CN/fixed-tower` 是百度推广第一梯队产品落地页之一，承接关键词包括：

- 钢结构训练塔、消防训练塔  
- 双窗训练塔、框架式训练塔  

策略文档要求路径为 **产品页 → 询盘（1 跳）**，质量度与转化高度依赖落地页相关性与扫读效率。

### 1.2 当前观感结论（2026-08-04）

| 维度 | 判断 |
|------|------|
| 图文比 | 原先几乎仅有 Hero；已临时接入 overview / 系列 / 定制 三张概念图，但仍偏「说明书」 |
| 信息密度 | 文案块多、卖点重复（overview ↔ 对比表 ↔ 定制列表） |
| 决策路径 | 「标准 vs 定制」出现偏晚，系列「15 套」可视化不足 |
| 投放适配 | 中段缺少 CTA；全站 StatBand / 6 步流程偏品牌叙事；促销弹窗可能干扰 SEM |
| 词面缺口 | 正文有「钢结构 / 框架」，**几乎无「双窗」**（百度高频规格词） |

### 1.3 方案目标

1. **30 秒内**让访客完成：看懂产品 → 选标准/定制 → 触发咨询或下载规格  
2. **提升百度质量度相关信号**：关键词可见（扫读层）、图文相关、bounce 可控  
3. **不破坏站内设计系统**：延续 Rosenbauer 工业风（锐利、少卡片、全宽视觉锚）  
4. **合规不回退**：不引入虚假年限、绝对化、无出处规模数据（见合规文档）

**非目标（本方案不做）**：重做全站导航、改模块化/燃烧室页、上生产 AI 概念图当「工程实拍」、改全站公共 `blocks.processBand` 文案（见 §4.2 P1-4）。

## 三、业内最佳实践（工业资本品产品线页）

对标对象：Rosenbauer 等消防/训练设施厂商产品线页、以及 B2B 资本品 SEM 落地页常规结构。

### 3.1 访客 30 秒任务模型

```
看懂长什么样 → 选标准还是定制 → 留下线索（咨询 / 下载规格）
```

### 3.2 推荐信息架构

```
Hero（产品本体 + 主 CTA）
  → SpecStrip（唯一数字/规格扫读层；含关键词词面）
  → Overview（短文 + 整塔大图）
  → 双路径选型（标准 | 定制 = 原 Compare 前移合并；Custom 长列表下沉）
  → 系列缩略网格（复用 series 四卡 → /series）
  → 中段 CTA
  → 信任条（案例 / 图标，P2）
  → 本页专用交钥匙短流程（勿改全站 ProcessBand 文案）
  → 相关延伸 + 终局 CTA
```

### 3.3 与「品牌介绍页」的差异

| 品牌介绍页 | 采购决策落地页（本方案取向） |
|------------|------------------------------|
| 长价值主张段落 | 短标题 + 规格标签 + 图 |
| 全站公司数字 | **仅 SpecStrip**（产品向，可核验） |
| 完整特性 checklist | 每路径 3～4 条关键差异，细则下沉子页 |
| CTA 仅首尾 | 首屏 + 中段 + 尾屏 |
| 通用弹窗促销 | 付费流量不打断（运营排除或 UTM） |

### 3.4 设计系统约束（本仓库）

- 延续 web 工业风：锐利圆角、少「卡片装饰」、区块一职一目的  
- Hero 保持全宽视觉；勿在 Hero 叠浮层徽章/促销贴片  
- 用户可见文案走 i18n（zh-CN / zh-TW / en 同步）  
- 媒体路径走 `/media/…` → 对象存储 `content/…`（`MediaImage` + sync）  
- **SpecStrip 移动端**：允许换行（2 行内）或横向轻滑；禁止变成多行文字墙；桌面为一行扫读标签

## 四、优化方案（分优先级）

### 4.1 P0 — 投放相关 / 转化敏感（Wave A）

| ID | 项 | 做法 | 预期 |
|----|----|------|------|
| P0-1 | 系列可视化选型 | 系列区改为 **4 张塔型卡**，数据复用 `pages.fixedTowerSeries.series`（§2.2）；卡点击/「查看全部」→ `/fixed-tower/series` | 兑现「15 套」预览承诺 |
| P0-2 | SpecStrip（唯一规格层） | Hero 下增加规格扫读条；**本页去掉 `StatBandI18n`**，不另开第二数字带。建议标签（可核验）：钢结构 · 框架式 · 最高 7 层 · 15 套布局 · 全镀锌 · NFPA 1400/1402 参照 · 燃烧室高温能力。**「双窗」**：若产品事实可支撑，加入短标签或 overview 一句；若暂无核验事实，**不上词**，避免虚假相关 | 扫读 + 词相关；无数字噪音 |
| P0-3 | 中段 CTA | 系列网格后：「预约咨询 + 下载 PDF」 | 缩短转化路径 |
| P0-4 | 付费流量弹窗 | **双路径（可并行）**：① **运营最快**：活动 `excludePages` 加入 `/fixed-tower`（及必要时 `/fixed-tower/*`）；② **工程通用**：`utm_source=baidu`（及约定 CPC 源）抑制或延迟弹窗。Wave A 可先做 ①，Wave B 视需要做 ② | 降 bounce，护质量度 |

### 4.2 P1 — 结构减负（Wave B）

| ID | 项 | 做法 | 预期 |
|----|----|------|------|
| P1-1 | Overview 瘦身 | 1 标题 + 1 短段 + 整塔大图；删/并 lead+body 重复（Wave A 可先轻度做） | 图文比改善 |
| P1-2 | 双路径定稿 | **Compare 并入「标准 \| 定制」双路径**（各 1 图 + 3～4 条关键差异）；**Custom 区长列表下沉** `/fixed-tower/custom`，Hub 页不再保留完整定制 checklist + 完整对比双列 | 决策更快、去重 |
| P1-3 | （并入 P0-2） | ~~单独产品数字条~~ **取消**；产品指标只存在于 SpecStrip | 避免双重噪音 |
| P1-4 | 流程压缩 | **本页专用** 4 步横条（勘察 → 设计 → 交付 → 维保），文案进 `fixed-tower.json`；**禁止**直接改全站 `blocks.processBand`（首页等共用） | SEM 页更短且无全站副作用 |

### 4.3 P2 — 信任与素材真实度（Wave C）

| ID | 项 | 做法 | 预期 |
|----|----|------|------|
| P2-1 | 案例条 | 2～3 个固定塔相关案例缩略 → `/cases` | 社会证明 |
| P2-2 | 标准/服务图标条 | NFPA 参照、交钥匙、年检/质保等一行短标签 | 信任扫读 |
| P2-3 | 实拍替换概念图 | 自有实景优先；过渡期可用已 ETAG 校验的 `alarm-*` / 系列图 | 厂家可信度 |
| P2-4 | Hero 与 overview 分工 | Hero：场景/人员；Overview：整塔产品照 | 视觉层次清晰 |

### 4.4 明确不做或慎做

- ❌ 为「显得丰富」再加长文、再堆绝对化卖点  
- ❌ 无出处精确规模（项目数、年限叙事）回潮  
- ❌ 将未标注的 AI 渲染图表述为「交付实景」  
- ❌ 无产品事实时硬塞「双窗」等搜索词  
- ❌ 修改全站 `ProcessBandI18n` / `StatBandI18n` 公共文案来迁就本页  
- ⚠️ 系列网格勿做成电商式圆角大卡片墙，保持工业站排版

## 六、文案与合规要点

1. 规格条数字必须与现有可核验表述一致（如「最高可建 7 层」「15 套预设布局」）；新增精确数需台账。  
2. 「参照 NFPA 1400/1402」可保留为标准参照表述，避免改成「通过认证」等未核实说法。  
3. **CTA 标题改为中性问句**（默认采纳）：去掉「最适合」；同步改 `cta.description` 中同类措辞。  
4. 「双窗」：有事实则上 SpecStrip/overview；无事实则不上（§4.1 P0-2）。  
5. 三语同步：改 `fixed-tower.json` 时 zh-CN / zh-TW / en 一并更新；系列卡文案优先复用 `fixed-tower-series` 已有三语。
