采用标准 NestJS 分层结构：`customers.module.ts` 通过 `@Module` 声明控制器与提供者并导出 `CustomersService`；`customers.controller.ts` 使用装饰器定义 REST 路由，统一通过 `@ApiBearerAuth()` 和 `@RequirePermissions('customers.view'|'customers.manage'|'customers.delete')` 做鉴权，请求体由 DTO 类驱动校验；`customers.service.ts` 封装业务逻辑，直接依赖 `PrismaService` 操作数据库，并通过 `resolveContentAuthor` 记录操作人。DTO 集中在 `dto/customer.dto.ts`，使用 class-validator + class-transformer + Swagger 注解完成参数校验与文档生成。模块对外仅暴露 Service，Controller 不持有持久化依赖，依赖方向单向：Controller → Service → PrismaService。
