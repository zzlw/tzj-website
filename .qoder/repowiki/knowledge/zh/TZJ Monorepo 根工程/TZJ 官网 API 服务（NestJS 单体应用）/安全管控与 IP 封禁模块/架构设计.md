基于 NestJS 模块组织：`security.module.ts` 作为入口注册 `SecurityController`、`SecurityService` 和 `IpBanService`，并通过 `exports` 暴露给其他模块使用。
- 控制器层（`security.controller.ts`）通过 `@RequirePermissions('security.view'|'security.manage')` 权限装饰器保护路由，对外暴露 IP 流量查询与封禁管理 REST API。
- 服务层分为两类：`SecurityService` 负责基于 Prisma 原生 SQL 的 `page_views` 表聚合查询（按 `ipHash` 分组、脱敏展示），`IpBanService` 负责封禁名单的增删查与内存缓存（60s TTL 的 `Set<string>`）。
- 守卫层（`ip-ban.guard.ts`）实现 `CanActivate`，在 JwtAuthGuard 之后执行，仅拦截未认证访客请求，已登录用户一律放行以避免管理员自锁。
- DTO 层（`dto/create-blocked-ip.dto.ts`）使用 class-validator 校验入参。
- 依赖方向单向向下：Controller → Service → PrismaService；Guard 依赖 IpBanService 但不被其反向依赖。
