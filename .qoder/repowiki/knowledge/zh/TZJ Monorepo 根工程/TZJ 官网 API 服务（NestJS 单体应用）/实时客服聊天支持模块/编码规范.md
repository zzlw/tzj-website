- DTO 类统一使用 class-validator 装饰器（@IsEmail、@IsNotEmpty、@IsEnum 等）+ class-transformer（@Type）进行请求体校验，且必须值导入而非 import type，以保证 NestJS 运行时能解析 design:paramtypes。
- 权限控制通过 `@RequirePermissions('chat.view'|'chat.manage'|'chat.delete')` 装饰器声明，删除操作强制要求更高权限 `chat.delete`，普通客服仅持有 `chat.manage`。
- 所有需要身份的操作在 WebSocket 侧通过 `getAuth()` 守卫从 `client.data.auth` 推导发送者身份，绝不信任客户端报文中的 sender 字段，形成 C1/C2/C3 安全闭环。
- 服务间依赖注入统一使用 `// biome-ignore lint/style/useImportType: NestJS DI 需要类作为运行期注入 token` 注释来豁免 import type 检查，因为 NestJS 需要在运行时获取类引用。
- 错误处理采用 try-catch 包裹后统一转换为 `HttpException`，并区分 `instanceof HttpException` 直接透传，其他异常包装为 BAD_REQUEST。
- Redis 相关功能通过 `CHAT_REDIS` 常量 + `useFactory` 工厂函数提供，未配置 `REDIS_URL` 时返回 null，各组件自行判断空值走内存回退。
