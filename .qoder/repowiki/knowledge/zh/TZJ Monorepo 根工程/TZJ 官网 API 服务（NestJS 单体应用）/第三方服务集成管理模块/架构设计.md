模块基于 NestJS 的 `IntegrationsModule` 统一注册 Controller、Service 与各第三方 Service（`AliyunCaptchaService`、`AliyunDmService`），对外通过 `integrations.controller.ts` 暴露三类 REST 端点：C 端公开配置（`/public`）、管理员概览（`/admin`）和凭据更新（`PUT :slug`）、连接测试（`POST :slug/test`）。

核心分层如下：
- 注册表层（`integration.registry.ts`）：以 `INTEGRATION_REGISTRY` 数组作为所有集成的唯一元数据源，定义 slug、label、secretFields/configFields、setupGuide、docUrl 等，并导出 `INTEGRATION_ENV_FALLBACK` 用于 DB 未配置时的环境变量兜底。
- 服务层（`integrations.service.ts`）：封装密钥解析（DB 加密优先 → env 兜底）、启用状态判断（`isActive`）、公开配置聚合（仅 `public: true` 字段）、管理员概览与凭据 upsert（使用 Prisma 的 `upsert` 按 slug 自动创建/更新）。
- 业务实现层：每个第三方服务独立一个 `*.service.ts` 文件（如 `aliyun-captcha.service.ts`、`aliyun-dm.service.ts`），通过注入 `IntegrationsService` 获取凭据，调用对应阿里云 SDK。
- 测试层（`integration.testers.ts`）：以 `Record<string, IntegrationTester>` 形式注册各集成的连接测试逻辑，由 `IntegrationsService.testConnection` 分派。
- 校验层（`integrations.schema.ts`）：基于 Zod 定义 `updateIntegrationSchema`，并在 Controller 中做请求体校验。

依赖方向单向：Controller → Service → (PrismaService + ConfigService + 第三方 SDK)，第三方 Service 反向依赖 IntegrationsService 读取凭据，避免循环依赖。
