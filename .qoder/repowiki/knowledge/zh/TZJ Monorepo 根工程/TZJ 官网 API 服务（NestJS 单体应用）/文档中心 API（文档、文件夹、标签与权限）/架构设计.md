模块以 `documents.module.ts` 为 NestJS 模块入口，通过 `@Module` 注册 `DocumentsController` 及四个 Service：`DocumentsService`（文档核心业务）、`DocFoldersService`（文件夹树与排序）、`DocTagsService`（标签注册表与合并/重命名）、`DocumentPermissionsService`（按用户/角色/公开维度的访问控制）。Controller 层仅做路由装饰、参数校验与权限守卫转发，所有业务逻辑下沉到对应 Service；Service 之间通过依赖注入协作（如 `DocumentsService` 调用 `DocTagsService.ensureTags` 和 `DocumentPermissionsService.checkAccess`），并统一通过 `PrismaService` 操作 `internalDocument`、`docFolder`、`docTag`、`documentPermission` 等 Prisma 模型。DTO 集中在 `dto/` 子目录，使用 class-validator + Swagger 注解完成入参校验与 OpenAPI 描述。权限判断采用双层：Controller 层用 `@RequirePermissions('docs.*')` 守卫粗粒度操作授权，Service 层再结合 `ownerId` 与 `documentPermission` 表做细粒度资源级鉴权。
