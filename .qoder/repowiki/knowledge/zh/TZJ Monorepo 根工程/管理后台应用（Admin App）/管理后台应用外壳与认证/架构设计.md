模块以 Next.js App Router 为骨架，分三层组织：
- 根布局 `app/layout.tsx` 定义全局 HTML/元数据与全局 Toaster；`app/globals.css` 提供主题变量。
- 登录入口 `app/login/page.tsx` 为纯客户端表单，调用 `/api/auth/login` 写入 httpOnly Cookie（access/refresh），成功后 `router.replace(from || '/')` 并 `router.refresh()` 触发服务端重定向校验。
- `(dashboard)` 路由组是所有受保护页面的父级：`layout.tsx` 在服务端通过 `getSession()` 校验会话，失败则 `redirect('/login')`；再通过 `apiFetch('/auth/me')` 拉取权限列表，读取 cookie 中的 `sidebar_state` 作为侧边栏默认展开状态，并获取公开水印配置；随后用 `Providers` 包裹 `SessionProvider`、`QueryProvider`、`VisitorDrawerProvider`、`ChatPresenceProvider`，再套入 `DashboardShell` 组件。
- `DashboardShell` 是客户端壳层，基于 `@tzj/ui` 的 `SidebarProvider` + `ScrollArea` 实现固定视口 + 内部滚动，侧边栏收起/展开状态通过 URL 参数 `?nav=collapsed|expanded` 持久化（无参时回退到服务端 cookie），同时可选渲染 `ScreenWatermark` 全局水印。
- API 层位于 `app/api/`：`auth/login` 和 `auth/logout` 直接操作 Cookie；其他路由（如 `bff/[...path]`、`chat/token`、`media/*`）作为 BFF 转发至后端 `API_BASE`。
依赖方向单向向下：`(dashboard)/layout.tsx` → `Providers` → `DashboardShell` → 各业务 page；认证流程由 login page → api/auth → 后端服务，再由 layout 的 `getSession` 反向校验。
