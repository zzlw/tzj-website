模块采用 Next.js App Router + React Server Components 边界划分：`app/(dashboard)/chat/page.tsx` 作为页面入口，仅负责布局高度与 `Suspense` 包裹；核心业务集中在 `features/chat/ChatMessenger.tsx`，集中管理五类分桶（all/waiting/active/closed/archived）的本地状态、HTTP 分页拉取与 Socket.io 实时事件合并。
- 数据层：`api.ts` 统一通过 BFF `/api/bff` 代理发起 REST 请求（自动携带鉴权），`useChatSocket.ts` 封装 Socket.io 连接、事件订阅与命令发送（join/leave/send-message/markRead/updateStatus/transferRoom 等），两者共同构成「REST 列表 + WebSocket 实时」的双通道数据源。
- 状态层：`ChatPresenceProvider.tsx` 在 dashboard layout 层级持有全局 socket 连接与坐席 presence 状态，每 10 分钟刷新 chat token 并在 auth-error 时自动重连；`ChatMessenger` 内部用 `buckets: Record<BucketKey, BucketView>` 维护各分桶的 rooms/cursor/hasMore/loading 状态，并通过 `mergeRooms`、`moveRoomToBucket` 等纯函数保证 HTTP 与 socket 数据的一致性。
- 表现层：`components/` 下按职责拆分 UI 组件（ChatArea、ChatConversationList、ChatMessageBubble、ChatMessageComposer、VirtualList 等），其中 `VirtualList.tsx` 是零依赖的固定行高窗口化列表，用于万级条目性能优化。
- 依赖方向：page → ChatMessenger → components / api / useChatSocket / ChatPresenceProvider；types.ts 为共享类型定义，被 api、socket 与所有组件引用，形成单向依赖。
